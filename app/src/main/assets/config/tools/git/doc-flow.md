# Git 流程手册（命令组）

## `daily-git` 日常开发提交流程

按顺序执行：**拉取最新代码 → 提交并推送**。

### 执行顺序

1. `git-pull`：先同步远程，避免推送时冲突
2. `git-commit-push`：填写提交信息与分支后推送

### 适用场景

- 每天开工前的常规同步
- 单人维护分支、冲突概率低的场景

## `git-conflict-flow` 拉取冲突处理流程

按顺序执行：**暂存改动 → 拉取 → 恢复改动 → 提交推送**。

### 执行顺序

1. `git-stash-pop`：把本地改动收进 stash 并顺带拉取、恢复
2. `git-pull`：确认已是最新
3. `git-commit-push`：提交并推送

### 注意

- 第 1 步的 `stash pop` 若报冲突，先解决冲突再继续
- 该流程跨命令组复用了核心命令，改动核心命令会同步生效

## `deploy-web` 跨工具组说明

「快速部署 Web 服务」组定义在 Docker 工具下，复用了本工具的 `git-pull`，
说明命令组可以跨工具引用命令，只需填写目标命令的 `id`。
